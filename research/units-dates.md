# Исследование: единицы измерения и даты

Здесь только варианты. Решение принимает пользователь, рекомендация помечена **[Рекомендация]**.
Цель: `3 kg in mg`, `now - 3 days`, `31 dec - today`, `10 kg - 10%` — в той же строке, тем же конвейером.

## 1. Главная идея: валюта — частный случай «единицы»

Сейчас в конвейере всё завязано на `CurrencyCode`: токен `Currency`, узлы `WithCurrency`/`Convert`,
тип `Typed.Sum`, `Value.Money`. Но правила языка выражений не про валюты, а про «число с единицей»:
- `+`/`-` приводят правую к левой, результат в первой слева (`120 eur - 100 usd`) → `1 km + 500 m` = 1.5 km;
- ×/÷ на число, `a ± p%`, `to` (в т.ч. `100 to eur`), голая единица = 1, отношение `÷` → `Ratio`,
  голое число + единица = ошибка — всё переносится без изменений.

Различается только **как конвертировать**: валюта — через `RateTable` (динамика), мера — через
таблицу множителей (статика), температура — через множитель и сдвиг.

Итого: `Currency` → `Measure` (единица), у неё есть `dimension`; валюта — одно из измерений.

## 2. Модель

```
core/Measure.kt
  sealed interface Measure { Currency(code) ; Physical(id) }      // id: "kg", "h", "c"
  enum Dimension { Currency, Length, Mass, Volume, Area, Temperature, Time, Data, Speed, ... }
core/Catalog     (серый ящик, данные) id → dimension, factor к базе (BigDecimal из строки), offset
```
- Измерение — enum, не вектор степеней. Производные (площадь, скорость) — отдельные измерения со своими
  единицами в каталоге. `m * m`, `km / h` — ошибка, как `usd * eur`. Вектор степеней (`m²`, `km/h` из частей)
  — «позже»; из enum в вектор мигрировать можно, каталог не переписывается.
- Время — обычное измерение (`3 days`, `2 h to min`). Длительность = `Quantity` в Time, отдельного типа нет.
- Месяц и год: в каталоге среднее (год = 365.2425 д, месяц = год/12), но при прибавлении к моменту
  целое число месяцев/лет — календарное (`plusMonths`), дробное — по среднему.
- Температура: `to` учитывает сдвиг (`25 c to f`); `+`/`-` только внутри одной единицы, смешанные — ошибка.

Значения (`calc/Calculation.kt`):
```
Value.Money(amount, CurrencyCode)          -- как сейчас, UI топ-N не ломаем
Value.Quantity(amount, Measure.Physical)   -- новое: 3 kg, 72 h
Value.Moment(at: LocalDateTime, dateOnly)  -- новое: now - 3 days
```
`Calculation.Ok.currencies` → `measures: Set<Measure>` (для frecency).
Новые ошибки `CalcError`: `IncompatibleUnits` (`3 kg + 2 m`, `3 kg to m`, `10 usd to kg`), `BadDate`
(`31.02.2026`), `BadMomentOp` (`now + now`, `now * 2`). Существующие `MixedNumberMoney` и др. переиспользуются
для мер (переформулировать текст в ресурсах).

## 3. Даты и время

**Момент — новый тип, `Moment ± Длительность = Moment`, `Moment − Moment = Длительность`.**
Остальное — ошибка (`now + now`, `now * 2`, `now to kg`).

Слова: `now today tomorrow yesterday` / `сейчас сегодня завтра вчера`. Литералы:
- `2026-12-31`, `31.12.2026`, `25 dec`, `dec 25`, `25 декабря 2026`, время `14:30`;
- **неоднозначное запрещено**: `12/25`, `03/04/2026` — ошибка «уточните формат», как `kr`.
  Год не указан — текущий (берётся из `now`, детерминировано).
- `2026-12-31` лексер обязан распознать целиком раньше числа, иначе это `2026 − 12 − 31`. Аналогично
  `31.12.2026`: не пересекается с `1.000.000` (последняя группа из 4 цифр и месяц ≤ 12).
- `:` сейчас не используется; «`:` как деление» (было отложено) снимается в пользу времени.

Результат: `now - 3 days` → «22 сент 2026, 14:03». `Moment − Moment`: оба dateOnly → дни, иначе
крупнейшая единица, в которую целое ≥ 1 (д, ч, мин). Ниже — карточки других единиц времени (как топ-N).

**Часы.** Калькулятор — чистая функция без состояния, `now` ей взять неоткуда. Как курсы, время
приходит параметром: `Calculator.calculate(text, env: Env)`, `Env(rates: RateTable, now: ZonedDateTime)`.
Тесты детерминированы. Результат — снимок на момент ввода, тиканья нет (пересчёт при правке/курсах).
Меняются контракты `Calculator`, `Evaluator` (см. §7).

Не сейчас: пояса (`now to tokyo`; имена городов на RU — большой словарь, `android.icu` в `core` нельзя),
`next friday`, `в 9:00` (`в` уже = `to`), цепочки `1h 30m`, разница в «3 месяца 7 дней».

## 4. Слова: конфликты — главный риск

Лексер сопоставляет слово целиком, без регистра. Единицы добавляют сотни коротких слов, часть
конфликтует с существующими. Проверка конфликтов при сборке словаря уже есть — теперь она работает между
доменами (валюты, меры, время).

Реальные конфликты:
| слово | сейчас | конфликт | предложение |
|---|---|---|---|
| `m`, `м` | множитель ×10⁶ | метр | **убрать `m`/`м` из множителей**, оставить `млн`, `mln`; `к`/`k` = тысяча остаются |
| `in` | `to` | дюйм | дюйм только `inch`, `дюйм`, `″`; `in` остаётся `to` |
| `k` | множитель | кельвин | кельвин только словом `kelvin`, `кельвин` |
| `в` | `to` | «в 9:00» | не поддерживаем |
| `фунт`, `pound` | (GBP) | фунт массы | неоднозначное (`Ambiguous` с валютой и мерой), «уточните: gbp/lb» |
| `ton`, `gallon`, `pint` | — | US/UK | неоднозначные; однозначные `usgal`, `ukgal`… |
| `dram`, `won` и т.п. | валюта | редкая мера | меру не заводим |
| `mar`, `may`, `sun` | — | месяц/день | не конфликтуют, но растёт префиксный набор `Incomplete` |

`Meaning.Ambiguous.options` обобщается с `List<CurrencyCode>` до `List<Measure>`. Правило «неоднозначное
запрещено всегда, независимо от контекста» сохраняем — иначе разбор начнёт зависеть от соседних слов
(отклонённый вариант: `10 pounds to kg` угадывает по цели; удобнее, но `pounds` в другом выражении
означает другое, и чипы уточнения так решают то же).

**SI-приставки не перечисляем руками**: билдер словаря генерирует `milli/kilo/… × {g, m, l, s, byte…}`
из белого списка базовых единиц, для RU — приставка + форма основы (`кило`+`грамм/грамма/граммов`).
Всё равно данные, а не код; конфликты ловятся той же сборкой.
Регистр не различаем: `mb` — всегда мегабайт, биты только словом (`mbit`).

Позиция единицы: префикс (`$10`, `usd 10`) — только у валют; у мер только суффикс (`10 kg`), голая `kg` = 1 kg.

## 5. Конвейер и код

Лексер, балансировщик, парсер, вычислитель остаются; расширяются данные и узлы:
- `Token.Currency` → `Token.Unit(Measure)`; `Node.WithCurrency`/`Convert(target: CurrencyCode)` → `WithUnit`/
  `Convert(target: Measure)`; добавляются `Token`/`Node` для `now…`, дат и времени. Грамматика: `primary` получает
  `Date [Time]` и `Now`; остальное — тот же `Number [Scale] Unit`.
- `Typed.Sum` → `Typed.Qty(amount, Measure)` + `Typed.Moment`. `amountIn` ветвится: валюта → `rates`,
  мера → каталог, разные измерения → `IncompatibleUnits`.
- Словарь `Lexicon.kt` (~260 строк, все валюты) делится: `CurrencyLexicon`, `UnitLexicon`, `TimeLexicon`,
  общий `Lexicon.Builder` собирает и проверяет конфликты.
- Зависимости: **ноль**. `java.time` уже используется (`core/Rates.kt`, minSdk 26). Библиотеки единиц
  (indriya/JSR-385: рефлексия, service-loader) и разборщики дат (natty, prettytime) тяжелы для сборки на
  телефоне и тащат свои правила слов — отклонены.

## 6. UI

- **Топ-N и frecency по измерениям.** Идея frecency для валют переносится: `3 kg` сразу показывает mg, g, lb, oz… — рейтинг
  единиц того же измерения. Засев по локали: метрика/имперка (`Locale.getDefault()`), температура C/F.
  Frecency хранит счёт по ключу `Measure` (одно хранилище, ключ — строка), `ranking(dimension)`.
  `CurrencyFrecency`/`CurrencyUsage` обобщаются в `MeasureFrecency`.
- `Conversions` сейчас считает строки из `RateTable` прямо в composable (`ui/CalculatorScreen.kt`). Вынести в
  чистую функцию `alternatives(value, ranking, env): List<Value>` — тестируется на JVM, UI только рисует.
- Моменты: одна крупная карточка + пара карточек (день недели, ISO). Длительность — карточки единиц времени.
- Чипы подсказок и диалог «+»: `currenciesWithPrefix` → `measuresWithPrefix`; в диалоге группы по измерениям.
  Слово, с которого начинаются и валюта, и мера (`m`), покажет обе.
- Формат чисел (`format(…, maxFraction)`, временный): у мер нет «знаков валюты», нужна таблица знаков на
  измерение или значащие цифры — решается вместе с форматированием чисел.

## 7. Контракты, которые придётся менять
- `calc/Calculation.kt`: `Value` (+`Quantity`, `Moment`), `Calculation.Ok.currencies`→`measures`, `CalcError` (+3).
- `calc/Calculator.kt`, `calc/engine/Stages.kt` (`Evaluator`): `rates` → `env`.
- `core/Rates.kt` не меняется; новый `core/Measure.kt`, `Env`.
- `core/Frecency.kt`: `CurrencyFrecency`/`CurrencyUsageStore`/`CurrencyUsage` → по `Measure`.
- `core/Primitives.kt`: `CurrencyCode` остаётся, `Measure` рядом.

## 8. Порядок работ **[Рекомендация]**
1. **Меры без времени.** `Measure`, каталог (длина, масса, объём, температура, данные), лексикон, `Quantity`,
   `to`, `+`/`-`, топ-N по измерению. Даёт `3 kg in mg` и проверяет обобщение до времени.
2. **Время как мера + Moment.** Единицы времени (`3 days to hours`), `Env(now)`, `now/today/…`, `Moment ± Duration`.
   Даёт `now - 3 days`.
3. **Литералы дат** (`31 dec`, `2026-12-31`, `14:30`), `Moment − Moment`.
4. Позже: пояса, `next friday`, `1h 30m`, составные единицы (вектор степеней), `km/h`.

Шаг 1 не трогает часы и `Moment` — `Env` и `Moment` появляются только на шаге 2.

## 9. Открытые вопросы к пользователю
1. `m`/`м` убрать из множителей в пользу метра? (рекомендация: да, `млн`/`mln` остаются)
2. Неоднозначные слова (`фунт`, `ton`, `gallon`) — строго запрещать, как `kr`, или выбрать одно значение по умолчанию?
3. Обобщать frecency сразу или на первом шаге оставить валюты, а меры ранжировать по засеву?
