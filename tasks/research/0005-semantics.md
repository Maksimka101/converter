# #5 Семантика выражений: черновик

Статус: **предложение, не решение**. Открытые вопросы помечены **[?]**, отложенное помечено **[позже]**.
Связано с: #4 (скобки), #6 (точность), #7 (RU/EN), #8 (frecency), #9 (топ-N), #10 (незаконченный ввод), #20 (домашняя валюта).

## 0. Принципы
- Сценарии: отпуск и подготовка к нему, сравнение цен в разных странах, разница цен. Всё прочее вторично.
- Выражение даёт **одно значение**: сумму в валюте, безразмерное число или процент.
- Результат в валюте сразу показывается в топ-N (#9), поэтому «валюта результата» задаёт только
  главную строку и округление, а не то, что увидит пользователь.
- Без единиц измерения, дат и переменных. Всё это **[позже]**, если вообще понадобится.

Мок-курсы для примеров: **1 usd = 0.9 eur = 90 rub = 36 thb** (1 eur = 100 rub, 1 thb = 2.5 rub).
Внутри считаем с полной точностью, при выводе округляем по валюте (#6). Топ-N в примерах: rub, usd, eur, thb.

## 1. Грамматика (эскиз)
```
input     = expr [ conv ] ;
conv      = convKw currency ;                       (* только в конце, одна цель *)
convKw    = "to" | "in" | "в" | "на" | "→" | "->" ;
expr      = term { ("+" | "-") term } ;              (* левоассоциативно *)
term      = unary { ("*" | "×" | "/" | "÷") unary } ;
unary     = { "-" | "+" } pct ;
pct       = primary [ "%" [ ofKw unary ] ] ;         (* 10%  |  10% of x *)
ofKw      = "of" | "от" ;
primary   = amount | currency | "(" expr ")" ;       (* скобки: правила в #4 *)
amount    = [ currency ] number [ scale ] [ currency ] ;
number    = digits { group digits } [ decSep digits ] ;
group     = " " | "_" | "'" ;                        (* 1 000, 1_000, 1'000 *)
decSep    = "." | "," ;                              (* см. 1.1 *)
scale     = "k" | "к" | "тыс" | "m" | "м" | "млн" ;  (* [?] см. 1.2 *)
currency  = code | symbol | name ;                   (* usd, $, доллар/баксов (#7) *)
```
Приоритет (от слабого к сильному): `conv` < `+ -` < `* /` < унарный `-` < `%`/`of` < скобки.
Возведение в степень `^` **[позже]**: для сценариев не нужно.

### 1.1 Десятичный разделитель [?]
- **A (предлагаю):** `.` и `,` оба десятичные; группировка только пробелом, `_` или `'`.
  `1,000` = 1.0. Плюсы: RU-привычка `1,5` работает, правило одно, нет угадывания. Минусы: EN-пользователь,
  набравший `1,000`, получит 1 (смягчается тем, что на телефоне так почти не пишут).
- **B:** эвристика: `,` + ровно 3 цифры = тысячи (`1,000` = 1000, `1,50` = 1.5). Минус: `1,500` неоднозначно, сюрпризы.
- **C:** если в числе есть оба знака, последний десятичный (`1,000.50` = 1000.5, `1.000,50` = 1000.5).
  Хорошо сочетается с A как расширение для вставки из буфера.
- Предлагаю **A + C**.

### 1.2 Множители `k/к/тыс/млн` [?]
- Удобно для отпуска (`15к руб`, `2 млн донгов`). Предлагаю: `k к тыс` = ×1000, `m м млн` = ×10⁶,
  только сразу после числа (с пробелом или без).
- Риски: конфликт с символами/кодами валют (`kr` у кроны, `м` без пробела), `10 м` как «метры», если единицы
  появятся **[позже]**. Правило: самое длинное совпадение побеждает, валюта важнее множителя.
- Альтернатива: не поддерживать в MVP. Минус: `15к` набирать естественно, а без него это ошибка.

## 2. Проценты
- `p%` сам по себе означает `p/100`, безразмерное число.
- **Особый случай:** `a + p%` и `a - p%`, где правый операнд сложения непосредственно процент,
  дают `a × (1 ± p/100)`. `a` может быть валютой или числом, а может быть уже накопленной суммой слева
  (`10 + 5 - 10%` = 13.5).
- `a * p%` = `a × p/100`; `a / p%` = `a ÷ (p/100)` (редко нужно, но без особых правил).
- `p% of x` / `p% от x` = `x × p/100`.
- Цепочка сложных процентов: `100 + 10% + 10%` = 121 (каждый процент берётся от накопленного).
- `10 usd%` — ошибка: процент от валюты без `of` не имеет смысла.
- **[?] «какой процент x от y»:** варианты `30 as % of 120`, `30 от 120 в %`, `30 / 120 в %`.
  Полезно для «на сколько процентов дешевле», но добавляет ключевые слова. Предлагаю **[позже]**,
  а пока хватает отношения (раздел 4): `30 usd / 120 usd` = 0.25.
- **[?]** Стоит ли отдельно «на сколько % дороже» (`1110 usd vs 1099 usd`)? Тоже **[позже]**.

## 3. Валюты и смешанная арифметика
- Токен валюты: ISO-код (без учёта регистра), символ (`$ € ₽ ฿ £`), название с RU/EN склонениями (#7).
- Позиция: до числа (`$10`, `usd 10`) и после (`10$`, `10 usd`). Две валюты у одного числа (`$10 eur`) — ошибка.
- Неоднозначные символы: `$` = usd, `р` = rub, `kr` **[?]** (sek/nok/dkk: по frecency или ошибка).
- Валюта без числа (`eur`) означает 1 единицу, это быстрый способ увидеть курс.

**Сложение и вычитание разных валют.** Всё конвертируется в валюту результата по текущим курсам.
Валюта результата — **[?]**:
- **A (предлагаю): первая валюта, встреченная слева направо.** `120 eur - 100 usd` = 30 eur.
  Плюсы: предсказуемо, совпадает с «из цены A вычесть B». Минусы: `-` не симметричен по валюте, но это и не нужно.
- **B: последняя валюта.** Похоже на «привести к последнему», но непривычно для `a - b`.
- **C: топ-1 по frecency / домашняя (#20).** Удобно в отпуске, но результат зависит от истории, а не от ввода.
- В любом варианте топ-N покажет то же значение во всех валютах, так что цена ошибки выбора невелика.

**Число без валюты рядом с валютой** в `+`/`-` принимает валюту соседа: `100 usd + 10` = 110 usd,
`10 + 5 usd` = 15 usd. Альтернатива: ошибка. Минус альтернативы: мешает быстрым правкам вроде `+ 10`.

## 4. Умножение и деление
| Операция | Результат |
|---|---|
| валюта × число, число × валюта | валюта |
| валюта ÷ число | валюта |
| число ÷ валюта | ошибка |
| валюта × валюта | ошибка («нельзя умножать валюту на валюту») |
| валюта ÷ валюта | **отношение**, безразмерное число (после конвертации в одну валюту) |

Отношение [?]: полезно для сравнения цен («в Германии в 1.11 раза дороже»).
- **A (предлагаю):** показывать как `×1.11`, топ-N скрыт. Можно дописать `(+11%)`.
- **B:** ошибка, а для сравнения ждать `as % of` **[позже]**. Минус: теряется простой и понятный кейс.

## 5. Число без валюты
- `2 + 2` = 4: чистый калькулятор. Главная строка «4», топ-N скрыт. **[?]**
- Альтернативы для голого числа (особенно одиночного `100`):
  - **A (предлагаю в MVP):** только число, топ-N пуст или показывает подсказку «добавьте валюту».
  - **B:** трактовать как топ-1 валюту по frecency и сразу конвертировать. Плюс: в отпуске набрал `1200`
    и видишь рубли. Минус: `2 + 2` внезапно становится деньгами, а топ-1 меняется со временем.
  - **C:** трактовать как домашнюю валюту (#20). Предсказуемее B, но требует настройки.
  - **D:** A, плюс вторым блоком тусклая строка «как <топ-1>: …». Компромисс, но экран шумнее.
- `100 to eur` **[?]**: ошибка «нет исходной валюты» (A), или 100 eur (просто показать курсы), или
  100 как топ-1 валюта (B). Предлагаю второе: цель без исходника = «покажи 100 eur».

## 6. Конвертация и вывод
- `expr to X` (и `in/в/на/→/->`) допустим только в конце, цель одна. Несколько целей (`to eur, rub`) **[позже]**.
- Конвертация посреди выражения (`10 usd to eur + 5`) — ошибка; вложение через скобки разрешено (решение #4): `(10 usd to eur) + 5`.
- Главная строка: результат в X (или в валюте результата, если X не задан).
- Топ-N при явном `to X` **[?]**:
  - **A (предлагаю):** X главной строкой, ниже обычный топ-N без X. Ничего не теряется.
  - **B:** показывать только X. Чище, но зачем тогда топ-N.
  - Явный `to X` повышает frecency X (#8).
- Исходная валюта выражения в топ-N не дублируется, если она уже в главной строке.
- Безразмерный результат (число, отношение, процент) показывается одной строкой, без топ-N.

## 7. Ошибка или незаконченный ввод (#10)
- **Незаконченный:** ввод является префиксом какого-то валидного ввода (парсер дошёл до конца, ожидая
  продолжения): `10 usd +`, `10 usd to`, `10 us`, `(10 + 5`, `10%` перед `of`.
  Показываем последний валидный результат (тускло), без сообщения об ошибке.
- **Ошибка:** никакое продолжение не спасёт, или ошибка типов: неизвестная валюта не являющаяся
  префиксом, `usd * eur`, `100 / 10 usd`, `1 / 0`, `+*`. Показываем последний валидный результат тускло
  и короткое пояснение (можно с задержкой ~0.5 с, чтобы не мигало при наборе).
- Ошибки типов считаем ошибкой сразу, хотя `10 usd * 5 eur / 1 eur` теоретически осмыслен
  (размерности не поддерживаем).
- **[?]** Неявный оператор: `10 usd 5 eur` — ошибка (предлагаю) или неявная сумма (как в Soulver).

## 10. Открытые вопросы (сводка)
1. Десятичный разделитель: A (оба десятичные) + C или эвристика B.
2. `k/к/тыс/млн`: поддерживать ли в MVP; конфликты с символами валют.
3. Валюта результата при смешении: первая (A), последняя (B), топ-1/домашняя (C).
4. Голое число: только калькулятор (A), топ-1 (B), домашняя (C), гибрид (D).
5. `100 to eur`: 100 eur или ошибка.
6. `валюта / валюта`: отношение `×1.11` или ошибка.
7. Топ-N при `to X`: X плюс топ-N (A) или только X (B).
8. Код до числа (`usd 10`), неоднозначные символы (`kr`).
9. Неявный оператор `10 usd 5 eur`: ошибка или сумма.
10. Показ одиночного `10%`: 0.1 или «10%».
