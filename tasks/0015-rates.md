## Суть
На старте работаем на моковых курсах. Интерфейс провайдера должен позволять потом подменить его
на настоящий источник с криптой; работа офлайн обязательна.

## Обсуждение / варианты
- Моки сразу включают крипту.
- Снапшот курсов в APK не кладём: при первом запуске нужен интернет.
- ЕЦБ / frankfurter как основной **отклонён**: ЕЦБ не публикует справочный курс RUB с марта 2022,
  рубля там нет. Резервным источником оставлять его смысла мало — покрытие у него подмножеством.

## Решение
**Мок и интерфейс** — принято 2026-09-24.
- Курсы — вся таблица целиком относительно базы, кросс-курс через базу: N чисел, а не N².
  Реальный источник тоже отдаёт один JSON на все валюты, грузить по валюте смысла нет.
- Калькулятор получает готовый снимок `RateTable` синхронно (`core/Rates.kt`). Загрузка и кэш —
  отдельно, вне `calc`. UI пересчитывает при изменении текста или курсов (`combine`).
- Курсов ещё нет → `NoRate`; если идёт загрузка, UI показывает «загружаем курсы» вместо ошибки.

**Реальный источник** — решено 2026-09-22, реализовано 2026-09-25.
- Источник — **только fawazahmed0/exchange-api** (бывш. currency-api): статические JSON на CDN
  jsDelivr, без ключа и лимитов, 200+ фиатных валют вместе с криптой, обновление раз в сутки.
  Запасной URL — `latest.currency-api.pages.dev`, зеркало того же источника, а не другой источник.
- Риск: это репозиторий одного человека на GitHub, а не институциональный API. Митигация —
  обязательный офлайн-кэш плюс абстракция `RatesProvider`, чтобы источник менялся в одном месте.
  Другой источник выберем, если этот начнёт подводить.
- **Сеть — голый `HttpURLConnection`**, не Ktor (закрывает вопрос из #2): один GET статического JSON,
  зависимость и её вес на телефоне не оправданы.
- **JSON — самописный парсер**, без `org.json` (стаб в JVM-тестах) и без kotlinx.serialization (плагин).
- **Кэш — один текстовый файл**, не Room (закрывает вопрос из #2): один снимок не стоит KSP-процессора
  на Termux; интерфейс `RatesCache` оставляет замену на Room открытой.
- Обновление: при старте и при каждом возврате в приложение, если кэш старше суток.
- Курсы показываются с датой снимка; сбой обновления не стирает старые курсы, а помечает их.

## Отложено
- Фоновое обновление через WorkManager.
- Порог «курсы сильно устарели» и заметное предупреждение: сейчас показывается только дата и пометка
  «не удалось обновить».
- Ручное обновление (кнопка / pull-to-refresh).

## Как реализовано
Контракт — `rates/RatesApi.kt` (гейты): `RatesSnapshot`, `RatesProvider`, `RatesCache`, `RatesRepository`.
`RatesSnapshot` нужен потому, что `RateTable` состав валют не отдаёт: снимок можно сохранить и перечислить.
- `rates/FawazRatesProvider.kt` + `RatesJson.kt`: основной URL, затем запасной; мусорный ответ основного
  тоже переключает на запасной. Кривые значения (<= 0, не число) пропускаются, USD добавляется, если его нет.
- `rates/FileRatesCache.kt`: `filesDir/rates.txt`, версия формата в первой строке, запись через temp + atomic move,
  битый файл читается как «кэша нет» и не удаляется.
- `rates/CachedRatesRepository.kt`: свежесть считается по `fetchedAt` (моменту загрузки), а не по дате курсов;
  `fetchedAt` из будущего считается устаревшим. Сбой сети или записи кэша не бросает, а идёт в `RatesState`.
- `CurrencyApp.kt`: репозиторий один на процесс, загрузка живёт в scope приложения и не обрывается на onStop.
  `MainActivity.onStart` дёргает `refreshRatesIfStale`. Пока курсов нет, в калькулятор идёт пустая `RateTable`
  (`NoRate`), а UI показывает «Загружаем курсы…» вместо ошибки.
- Frecency создаётся заново, когда меняется состав валют снимка (`DecayingFrecency` берёт список в конструкторе).
- Моки (`rates/MockRates.kt`) остались для тестов и превью, из приложения ушли.
