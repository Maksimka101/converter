## Суть
Выбрать библиотеки и структуру кода.

## Обсуждение / варианты
- Решено: чистый Android на Jetpack Compose. KMP/desktop не берём. Логику держим в чистом Kotlin, без `android.*`, чтобы потом можно было портировать.
- Принципы: как можно проще, меньше зависимостей (телефону тяжело), при выборе предпочитать кросс-платформенные варианты.
- Сеть, БД, тесты: без сильных предпочтений.
- Отдельные Gradle-модули `core`/`parser`/`app` отклонены 2026-09-24: обычный для Android один
  модуль `app` проще, а граница логики держится пакетами.
- Зависимости выбираем с оглядкой на сборку на телефоне: тяжёлые плагины, kapt/ksp-процессоры
  и нативные тулы могут не собраться под aarch64/Termux.

## Решение
Принято 2026-09-22.
- **UI**: Jetpack Compose, чистый Android.
- **Хранилище**: **Room** (androidx, есть версия под KMP). SQLDelight отклонён — у пользователя
  часто ломался даже на небольших проектах; голый JSON — слишком жёстко для истории и frecency.
- **Сеть**: в первой версии её нет — работаем на моке (#15), поэтому выбор библиотеки отложен
  до #17, чтобы не тащить зависимость, которой полгода никто не воспользуется. Кандидаты тогда:
  Ktor client (кросс-платформенный, в паре с KMP-Room сохраняет путь на другие платформы) против
  голого `HttpURLConnection` (источник — один GET статического JSON с CDN). Сериализация —
  kotlinx.serialization.
- **Числа**: `BigDecimal` за обёрткой `Num` в пакете `core` (#6).
- **Структура**: один модуль `app`, пакеты `core` (числа, валюты, frecency), `calc` (#3), `ui`.
  Всё, что не UI и не IO, живёт без `android.*`.
- **Тесты**: локальные unit-тесты `app/src/test` на JVM (гоняются без эмулятора).

## Как реализовано
Скелет собран 2026-09-23, 2026-09-24 сведён в один модуль `app`. Пакет и `applicationId` —
`com.zemlianikin.currency`. Версии — в `gradle/libs.versions.toml`. Тестовые зависимости и Room
пока не подключены, добавим вместе с первыми тестами и первой задачей с хранилищем (#8 или #12).
