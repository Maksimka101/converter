## Суть
Выбрать библиотеки и структуру модулей.

## Обсуждение / варианты
- Решено: чистый Android на Jetpack Compose. KMP/desktop не берём. Логику держим в чистом Kotlin, без `android.*`, чтобы потом можно было портировать.
- Принципы: как можно проще, меньше зависимостей (телефону тяжело), при выборе предпочитать кросс-платформенные варианты.
- Сеть, БД, тесты: без сильных предпочтений.
- Парсер вынесен в отдельный модуль (#3).

## Решение
Принято 2026-09-22.
- **UI**: Jetpack Compose, чистый Android.
- **Хранилище**: **Room** (androidx, есть версия под KMP). SQLDelight отклонён — у пользователя
  часто ломался даже на небольших проектах; голый JSON — слишком жёстко для истории и frecency.
- **Сеть**: в первой версии её нет — работаем на моке (#15), поэтому выбор библиотеки отложен
  до #17, чтобы не тащить зависимость, которой полгода никто не воспользуется. Кандидаты тогда:
  Ktor client (кросс-платформенный, в паре с KMP-Room сохраняет путь на другие платформы) против
  голого `HttpURLConnection` (источник — один GET статического JSON с CDN). Сериализация —
  kotlinx.serialization.
- **Числа**: `BigDecimal` за обёрткой `Num` в core (#6).
- **Модули**: `core` (чистый Kotlin: числа, валюты, frecency), `parser` (#3, чистый Kotlin),
  `app` (Compose, Room, сеть — позже). Всё, что не UI и не IO, живёт без `android.*`.
- **Тесты**: обычный JUnit на JVM для core и parser (гоняются без эмулятора).
