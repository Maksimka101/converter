## Суть
Какие валюты показывать и в каком порядке. Frecency (частота + давность) считается по валютам;
на ней строятся топ-N автоконвертации и порядок списка валют.
Результат сразу показывается в N самых популярных валютах, сколько влезает на экран (для начала 5),
как в Raycast — поэтому `to eur` нужен редко. Список валют пополняется автоматически.

## Обсуждение / варианты
- Риск: недонабранные токены (`eu`) могут засорить статистику.
- Порядок не должен прыгать во время ввода, иначе ломается мышечная память.
- Ресерч: [research/0008-frecency.md](research/0008-frecency.md) — варианты, плюсы и минусы, рекомендация (не решение).
- Открытый вопрос: N фиксировано (5) или считается по высоте экрана. Второе делает состав топа
  зависимым от устройства и ориентации, а порядок должен быть предсказуемым.

## Решение

### Frecency
Принято 2026-09-22. Рекомендация ресерча (C + E) с одной правкой: **все веса равны 1**.

**Момент засчитывания**
- Засчитывается множество **различных** валют итогового выражения, один раз на выражение.
- Триггер завершения: копирование результата, очистка поля, выход из приложения (`onStop`),
  пауза без правок ~3 с. Тот же триггер, что и запись в историю (#11).
- Промежуточные состояния ввода (`eu` → `eur`, backspace, правки) не засчитываются.
- Просмотр валюты в топ-N **не** засчитывается — иначе топ сам себя удерживает.
  Копирование конкретной строки топа (#11) засчитывает её валюту.

**Веса**
- Вес всегда 1: и источник, и явная цель `to`, и копирование строки топа.
  Отдельный повышенный вес для `to` отклонён — лишняя настройка без доказанной пользы.

**Формула и хранение**
- Экспоненциальный распад, период T = 21 день (константа, подобрать на практике).
- Хранится `score` + `updatedAt`, распад ленивый — при чтении и при добавлении.
- Валюты со `score` < 0.05 можно удалять из хранилища (как zoxide). Закрепления нет.

**Обновление порядка**
- Рейтинг пересчитывается **сразу** при каждой записи использования, без заморозки на время ввода
  (решено 2026-09-25; прежнее правило «только при старте/`onStart`» снято).
- Гистерезис (вытеснение только при перевесе 10–20 %) — опционально, если порядок окажется дёрганым.

**Холодный старт**
- Дефолты из локали (валюта + USD, EUR; валюта — явная `-u-cu-`, иначе регион из настроек телефона `-u-rg-`, иначе страна языка) засеиваются как «виртуальный»
  малый score (~1.0), который естественно распадается и вытесняется реальным использованием.
- Отдельного экрана выбора на первом запуске нет (противоречит #13).

**Связь с историей**
- Триггер общий с историей (#11), хранение раздельное: запись истории содержит список валют (для
  будущего пересчёта), frecency живёт в своём сторе. Очистка истории не обнуляет топ.

### Топ-N в результате
- Топ-N показывается и при явном `to X` (X главной строкой, ниже остальные без дублей).
  Безразмерный результат (число или отношение `×1.11`) показывается одной строкой без топ-N;
  процент в выводе сворачивается в число и тоже безразмерный (#5).
- Исключение из топа делает сессия/UI над рейтингом `CurrencyFrecency.ranking`, не frecency.
  Решено 2026-09-25: в выражении ровно одна валюта — она источник, из топа убираем; валют больше
  одной — источник неочевиден, ничего не исключаем. Дубли `to X` с главной строкой — по #5.

### Список валют
Принято 2026-09-22.
- Список пополняется **автоматически**: распознанная в выражении валюта попадает в список.
- Валюту можно добавить вручную: кнопка «+» в numpad (#13) ищет по названию и стране и засчитывает выбор во
  frecency. Рейтинг включает засев и все, что использовали, поэтому такая валюта появляется в чипах.
- **Экран редактирования пока не делаем**: ни закрепления, ни удаления, ни drag-сортировки
  (хотелки на потом) — чтобы не раздувать первую версию.
- Стартовый список — дефолты из локали (см. «Холодный старт»).
- На разбор выражения список **не влияет** (#5): неоднозначные токены (`kr`) запрещены всегда,
  по всему справочнику. Список задаёт только состав и порядок топ-N. Автопополнение ничего не ломает:
  максимум засоряет топ-N разово использованной валютой, и та сама выпадет по распаду.

### Отложено: домашняя валюта
Идея: задаёт, что значит голое `100`, и во что конвертировать по умолчанию. Концепция понравилась,
но не продумана. Под неё ничего не закладываем (#3), голое число пока — чистый калькулятор (#5).

## Как реализовано
Архитектура принята 2026-09-25 (интерфейсы — гейты в `core/Frecency.kt`).
- Калькулятор остаётся чистой функцией; AST и токены наружу не отдаём. Frecency берёт валюты из
  `Calculation.Ok.currencies` — все валюты, упомянутые во вводе. Разбор текста в frecency не дублируем.
- `CurrencyFrecency` — счёт, распад, засев по локали; отдаёт полный рейтинг. `CurrencyUsageStore` —
  только хранение (Room), без логики.
- Записывать валюты последнего валидного `Ok`, даже если текущий текст уже невалиден (#11).
- Триггер завершения выражения общий с историей: сессия ввода (ViewModel) выдаёт одно событие,
  подписываются frecency и история.

PoC (2026-09-25): `core/DecayingFrecency.kt` — счёт `score·2^(-Δt/21д) + 1`, засев `localeSeed` записывается в пустой стор
со score 1.0 (одно использование весит как засев). Стор — `data/PrefsUsageStore.kt` на SharedPreferences вместо Room.
Рейтинг — засев из `known` плюс всё, что записывали (засев вне `known` в стор не пишется, чтобы не попасть в рейтинг); остальные валюты со снимка в список не попадают, пока их не использовали или не добавили через «+» (решено 2026-09-25: не показывать сразу все). Вместо топ-N — весь этот рейтинг по убыванию frecency, главная строка без дубля;
исключение источника — только валюта главной строки. Список в `ui/CalculatorScreen.kt`.
Отступление от решения, только для PoC: валюты засчитываются **сразу**, как только во вводе появился новый набор валют
(один набор — один раз, пока поле не очистят), без триггеров копирования/паузы/`onStop`.
Вернуть по решению, когда появится сессия ввода (ViewModel). Заморозки рейтинга нет и не будет — см. «Обновление порядка».
