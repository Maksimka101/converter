# Задачи

Один md-файл на задачу: `NNNN-slug.md`. Готовые задачи не удаляются, это база знаний.

## Поля
- `status`: idea | discuss | todo | doing | done | dropped
- `priority`: high | medium | low
- `tags`: например parser, ui, core, rates, decision, backlog
- `depends`: id задач
- `updated`: обновлять при каждом изменении

## Разделы
Суть → Обсуждение / варианты → Решение → Как реализовано

## Индекс и проверка
- `./tasks/index.sh` пересобирает `tasks/INDEX.md`.
- `./tasks/lint.sh` ищет расхождения: битые ссылки `#N` и `depends`, пропавшие секции,
  `status: done` без «Как реализовано», `updated` старше правки файла, остатки процессных пометок.
- `./tasks/lint.sh N` — кто ссылается на #N.

## Гигиена
Правила выведены из разбора 2026-09-22, когда в файлах накопился мусор трёх видов.

1. **Инструкции агенту не живут в файле задачи.** `- [x] ревью ожидается от Claude` — это тикет,
   а не знание. Задание агенту идёт в промпт, в файл попадает только результат.
2. **«Обсуждение» — это отвергнутое и почему.** Всё принятое живёт в «Решении» и не дублируется
   выше по файлу. Приняв решение, вычисти из «Обсуждения» то, что оно закрыло.
3. **У решения есть радиус.** Решение в одном файле почти всегда закрывает вопросы в других.
   Записав «Решение», прогони `./tasks/lint.sh N`, пройди по всем ссылающимся задачам и вычеркни
   там то, что уже решено, заменив ссылкой «решено в #N». Это главный источник устаревания:
   в момент записи #7 нельзя было знать, что разделитель дроби решит #5.
4. **Одно утверждение — один файл.** В остальных ссылка `#N`, не копия.
5. **Меняя тело — проверь шапку**: статус, заголовок, priority, depends, updated.
6. Перед коммитом: `./tasks/index.sh && ./tasks/lint.sh`.
