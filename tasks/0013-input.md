## Суть
- Открыл приложение — фокус уже в поле ввода и системная клавиатура открыта.
- Над системной клавиатурой ряд, как extra-keys в Termux: `+ - * / % ( ) $ €` и т.п.

## Обсуждение / варианты
- `windowSoftInputMode` + `FocusRequester` для старта.
- Первая версия работает только с обычной (текстовой) клавиатурой.

## Решение
- **`(` для `)` без пары** (#5): набрал одну `)` — в текст вписывается настоящая `(`, курсор сдвигается.
  Только на ввод одного символа `)`; вставка и правки посреди текста текст не меняют. Позицию даёт
  `Calculation.Ok.virtualParens`; если результат не `Ok`, скобка не вписывается.
- **Пробелы при наборе** (`ui/InputEditing.kt`), только на один набранный символ:
  - `+ - * /` (и `× ÷ −`) получают пробелы с обеих сторон: `10+5` → `10 + 5`. Оператор бинарный,
    если слева операнд (цифра, `)`, `%`, слово, знак валюты), иначе унарный и остаётся вплотную:
    `-5`, `(-5)`, `10 + -5`. Слово `of`/`to` считается операндом, `of -5` получит лишние пробелы — безвредно.
  - число, `)` или `%`, за которыми набрана буква или знак валюты: `10usd` → `10 usd`.
  - после целого слова словаря (валюта, `to`, `of`, множитель), которое ничем не дорастает
    (`Lexicon.canExtend`): `usd` → `usd `, `to` → `to `. Не дорастающие слова решает словарь, а не список
    в UI: `in` (`inr`), `x`, `руб` (`рубль`), `rub` (`ruble`) пробела не получают. Одиночный `$` — не слово.
    Пробел, набранный сразу после пробела (в том числе авто-), игнорируется: двойной пробел нигде не нужен,
    а привычное нажатие после `usd`, `+`, `to` не ломает вывод.
  - `->` («to», #5): `-` с пробелами при вводе `>` становится `->`.
  - backspace по пробелу после ` + ` стирает оператор целиком; справа операнд — остаётся один пробел.
  - Пробел — разделитель разрядов (`1 000`, #5), поэтому пробелы у операторов и цифра–буква с ним не пересекаются.
  Скобки, `%` и `,`/`.` пробелов не получают. UI берёт `Lexicon.Default` из `calc.engine` напрямую.
- **Тип поля `KeyboardType.PasswordVisible`**, чтобы над буквами был ряд цифр: Gboard показывает его для
  парольных полей (так же, как в Termux), а для обычного текста он зависит от настройки пользователя.
  Не `Password`: он зовёт менеджер паролей (Dashlane), 2026-09-25. Побочно: без подсказок и запоминания ввода.
- Автокоррекция и заглавные выключены (`autoCorrectEnabled = false`; некоторые IME это игнорируют).

Отложено, без запроса не делаем:
- **Подсказки валют**: набираешь `до`, в ряду над клавиатурой появляются чипы USD/AUD. Это штатный способ
  разрешить неоднозначные токены (`kr`, в конце ввода — Incomplete без сообщения, #3), так что нужнее,
  чем кажется по статусу.
- **Режим numpad** с переключением в рантайме, последний режим запоминается: текстовая клавиатура
  (любая валюта в любую) и системный numpad (удобнее для математики). Ряд операций есть в обоих.
- **Доп. точки входа**: плитка в шторке; PROCESS_TEXT (выделил «100 usd» в любом приложении, открылось
  меню и конвертация). Пока только обычный запуск.

## Как реализовано
PoC в `ui/CalculatorScreen.kt`: `FocusRequester` в `LaunchedEffect` + `adjustResize` в манифесте.
На устройстве не проверено, замер холодного старта не делали. Ряда доп. клавиш пока нет.
Правки ввода — `ui/InputEditing.kt`, подчёркивание ошибки — `ui/InputTransformation.kt`.
Тесты — `ui/InputEditingTest.kt`: набор символов по одному через `editInput` с настоящим калькулятором, результат сравнивается как текст с курсором `|`; новое правило ввода = новая строка в таблице.
